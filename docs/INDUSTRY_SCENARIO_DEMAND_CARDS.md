# Industry Scenario Demand Cards

日期：2026-06-05

状态：产品需求工作稿。本文承接 `docs/MARKET_RESEARCH.md`、`docs/SOLUTION_PROVIDER_ICP.md`、`docs/PRODUCT_ARCHITECTURE_TRACE.md` 和 `docs/SCENARIO_ROI_MODEL.md`，用于把园区、厂区、仓储、景区的首批场景压成可访谈、可交付、可验收、可验证 ROI 的需求卡。

## Scope

每类只保留 3 个高价值场景。目标不是建立宽泛行业模板库，而是给方案商 Demo-to-pilot 交付提供可复用的 R4 场景验收卡、事件证据、客户签收材料和 acceptance dossier 输入。

硬边界：

- 不扩展成宽泛行业模板市场。
- 不把场景卡包装成生产上线承诺。
- 不把游客、访客或一线员工的一句话直接变成真实硬件动作。
- 不让页面、脚本或销售材料独立生成验收结论；验收事实必须来自 Field Delivery Domain。
- 需要真实执行时，只能通过受控 handoff 交给 Runtime / Safety / Hardware。

每张卡都必须回答：

| 字段 | 要求 |
| --- | --- |
| 买方痛点 | 方案商、交付 PM 或现场主管为什么愿意为这个场景付费 |
| 触发来源 | 人工、语音、VMS、传感器、机器人事件或工单 webhook |
| Field Delivery Domain 事实 | 项目、站点、对象、事件、证据、通知、关闭、客户签收 |
| 必要证据 | 截图、日志、照片、传感器记录、语音转写、处理人和时间线 |
| Runtime / Safety / Hardware 边界 | 哪些动作只能演练、影子记录或等待人工确认 |
| 验收信号 | 客户能否在 acceptance dossier 中逐条签收 |
| 禁止宣称 | 不能把试点证据说成生产可用或无人值守上线 |

## Architecture Use

这些卡不是页面文案清单，而是 Field Delivery Domain 的需求输入：

- `askme/pipeline/field` 应拥有场景、现场事件、对象绑定、证据、通知、关闭、客户签收和 acceptance dossier 事实。
- `askme/api/routes/field_*`、`askme/api/services/field_*` 和 Dashboard 只能展示、过滤和导出这些事实，不能独立发明通过/阻断结论。
- Runtime / Safety / Hardware 拥有真实执行和硬件状态；AskMe 只能记录受控 handoff、profile、人工确认和证据边界。
- customer signoff 只说明试点材料被客户签收，不等于 production readiness。

## Validation Plan

访谈时用 `docs/INTERVIEW_GUIDE_SOLUTION_PROVIDER.md` 和 `docs/SCENARIO_ROI_MODEL.md` 验证这些卡是否真的高价值：

1. 每个受访者最多选 3 个愿意验收或付费的场景，避免泛泛确认。
2. 要求提供脱敏项目材料、事件台账、验收目录或工单截图中的任意一种证据。
3. 如果某类行业的 3 张卡无法得到至少 2 个强信号，下一轮删除或降级该行业，不新增更多模板。
4. 对每张被选中的卡记录 baseline、target_delta、value metric 和 payback signal，缺少 usage evidence 时不能进入付费包装。
5. 如果客户要求新增场景，先记录为增长候选，不进入首批 R4 场景验收卡。
